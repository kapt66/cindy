## 技能 ID 硬入口与表级范围入口

战斗请求先分两类，判定发生在任何工具调用之前：

- `single-skill`：用户在当前任务中明确给出正整数技能 ID（带「技能 ID / 技能 / 编号」标签，或整条
  消息只有该正整数）。
- `table-scope`：范围由配置表或项目规则决定，用户没有给出技能 ID（例如「所有怪物技能」「怪物配置表
  里配置的正在使用的」「把某类技能的某个字段统一改成 …」）。

### single-skill

技能 ID 是用户指定的目标标识；当前模块配置入口要求技能 ID 为正整数。不得从 Unity 当前选中项、历史任务、搜索结果、相似配置、默认值或“最可能的技能”推断，也不得用节点 ID、技能表参数的负号引用（编码含义以注入的项目参考为准）或 `moduleType` 数值代替技能 ID。

如果缺少 ID，或 ID 是 `skill_001` 这类前缀/别名而没有明确数字映射，只能原样回复下面这一句话，不添加
原因、流程说明、示例或其它问题：

`请提供要生成、修改或检查的正整数技能 ID。`

随后结束当前轮，不读取项目文件、模块、客户端或服务器，不调用 Unity CLI、MCPRouter、P4，不生成
JSON，不导入/导出，也不从上下文尝试定位一个 ID。追问后的消息只包含一个正整数时即视为明确提供，不
要求用户重复“技能 ID”标签；一次出现多个技能 ID 且没有范围口径时仍使用同一句话，不擅自批量处理。
一旦 Host 已把用户提供的 ID 绑定到当前任务，后续业务澄清回复不要求用户重复携带 ID，也不得把“后续
消息没有再次写 ID”误判为缺失。

技能 ID 已明确且为正整数后，必须在内部方案和最终 `[SAGA2_COMBAT_CONFIG_RESULT]` 中原样记录
`targetSkillId`，并验证所有写入、当前技能导入/导出和最终核查都只针对该 ID 的范围。单技能任务只允许
这一个技能 ID；不得读取或导出参考技能，不得把历史样例、第二个 ID 或 reference marker 传给服务器
Worker。模块组合判断只使用当前目标导出、最窄客户端消费者与当前服务器 HEAD。

### table-scope

不得追问技能 ID，也不得套用单技能流程，**尤其不得回复「请提供正整数技能 ID」**（表范围请求没有、也
不需要单一 ID）。范围必须从请求声明的来源（配置表 / 规则文档）以有界只读证据
解析出来：先用 `legacy_module_query_nodes` 一次拿到命中节点全集（含归属 `skillId` 与现 `data`；
`truncated` 表示不完整，必须收窄后重试），再用 `legacy_module_audit_coverage` 分离只在导出 JSON 里、
没有 `.asset` 的技能，逐目标对齐可写表面，然后把「解析出的范围 +
精确改动集 + 超出表面清单 + 口径歧义」一次性交给用户确认。**确认前不得写入，也不得导入/导出**；
来源不可读或口径有歧义时停下来请用户裁定，不得自行选子集继续。启发式或推断得到的候选只能作为候选，
永远不能充当已确认绑定。

表级范围不使用 `targetSkillId`（写 `none`），范围写在 `targetSkillIds`，且只能包含用户已确认的目标；
其余要求与单技能一致：不得读取或导出参考技能，不得传递 reference marker。
