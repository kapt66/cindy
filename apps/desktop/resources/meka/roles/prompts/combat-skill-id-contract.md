## 技能 ID 硬入口

生成新技能、基于现有技能修改，或检查/核对技能时，必须先由用户在当前任务中提供明确的
技能 ID。技能 ID 是用户指定的目标标识；当前模块配置入口要求技能 ID 为正整数。不得从 Unity 当前选中项、历史任务、搜索结果、
相似配置、默认值或“最可能的技能”推断，也不得用节点 ID 代替技能 ID。

如果当前任务尚未由用户绑定唯一技能 ID：

1. 如果缺少 ID，或 ID 是 `skill_001` 这类前缀/别名而没有明确数字映射，只能原样回复下面
   这一句话，不添加原因、流程说明、示例或其它问题：
   `请提供要生成、修改或检查的正整数技能 ID。`
2. 结束当前轮，不读取项目文件、模块、客户端或服务器，不调用 Unity CLI、MCPRouter、P4，
   不生成 JSON，不导入/导出，也不从上下文尝试定位一个 ID；
3. 用户补充 ID 后，从该 ID 重新开始最小证据流程。追问后的消息只包含一个正整数时即视为明确
   提供，不要求用户重复“技能 ID”标签。若用户提供多个 ID，仍使用同一句话要求
   用户只提供本轮唯一目标，不擅自批量处理。

一旦 Host 已把用户提供的 ID 绑定到当前任务，后续业务澄清回复不要求用户重复携带 ID；始终沿用
该唯一目标，直到任务结束。不得把“后续消息没有再次写 ID”误判为缺失。

技能 ID 已明确且为正整数后，必须在内部方案和最终 `[SAGA2_COMBAT_CONFIG_RESULT]` 中原样记录
`targetSkillId`，并验证所有写入、当前技能导入/导出和最终核查都只针对该 ID 的范围。一个任务
只允许这一个技能 ID；不得读取或导出参考技能，不得把历史样例、第二个 ID 或 reference marker
传给服务器 Worker。模块组合判断只使用当前目标导出、最窄客户端消费者与当前服务器 HEAD。
