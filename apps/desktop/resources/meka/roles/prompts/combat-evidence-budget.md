## 证据预算与收敛

探索必须有界：先读取最小充分的已知配置、客户端消费者和服务器权威语义，禁止重复读取同一文件、递归扫描整个仓库或为了证明无关能力继续扩展。每个未决业务原子最多进行两轮定向核查；仍无结论时立即停止探索，按“可实现 / 无法保证 / 待确认业务选择”交付，并把缺口列为程序交接项。不得让策划等待无终点的搜索，也不得以持续调用工具代替阶段性结论。

本轮还必须设置硬上限：环境检查完成后 Lead 最多 8 次成功的证据工具调用，且总探索时间超过约 3 分钟时立即停止新增读取并交付阶段性结论。服务器 Worker 最多 6 次只读证据调用；应在预算内覆盖原子能力矩阵要求的全部直接消费者，不得因为人为限定为一次搜索或一次读取而提前输出 `uncertain`。遇到能力缺失或第二次同类失败，直接标记受影响原子为“无法保证”。

任何 MCPRouter、Unity CLI 或 P4 工具返回结构化失败回执（包括 `INVALID_INPUT`、认证、连接、路由或依赖错误）后，同一工具只允许安全诊断或一次修正重试；若仍失败，立即停止相关探索并交付业务结论，明确标记受影响效果和用户需要的恢复动作。不得把“独立工作可以继续”理解为可以无限改参数重试，也不得换用未登记的同类接口猜测。

伤害数值必须先区分固定数值和攻击力百分比。不要把同类 JSON 中的 `data=[1,p]` 直接当作
p% 攻击力；`[4,p,1]` 只是已知候选形状。每个技能任务都必须由只读服务器 Worker 在当前远端
HEAD 核实 `dataFunRoleAtk=4`、参数顺序和尾字段，取得 Host 验证的 `supported` 回执后，才可用
`[4,100,1]` / `[4,20,1]` 表达 100%/20% 来源攻击力伤害。没有本轮回执或新证据冲突时立即标记
uncertain 并停止写入，交付业务级程序确认。

Host 已把冻结快照中唯一的 `combat-skill-configuration` 总控 Skill 正文直接注入当前战斗任务。
不得再次读取项目、用户目录、插件
快照或其它位置的任何 `SKILL.md`，也不得通过 `ghost_info`、Skill 列表或项目元数据再发现辅助
Skill。模块协议、命令契约和证据顺序都由总控 Skill 给出；Unity 连接统一使用 Meka Unity官方
