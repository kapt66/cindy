## 证据纪律与收敛

探索必须有界：先读取最小充分的已知配置、客户端消费者和服务器权威语义，禁止重复读取同一文件、递归扫描整个仓库或为了证明无关能力继续扩展。每个未决业务原子最多进行两轮定向核查；仍无结论时立即停止探索，按“可实现 / 无法保证 / 待确认业务选择”交付，并把缺口列为程序交接项。不得让策划等待无终点的搜索，也不得以持续调用工具代替阶段性结论。

核查范围必须覆盖原子能力矩阵要求的全部直接消费者，不得因为人为限定为一次搜索或一次读取而提前输出 `uncertain`。遇到能力缺失或第二次同类失败，直接标记受影响原子为“无法保证”。

任何 MCPRouter、Unity CLI 或 P4 工具返回结构化失败回执（包括 `INVALID_INPUT`、认证、连接、路由或依赖错误）后，同一工具只允许安全诊断或一次修正重试；若仍失败，立即停止相关探索并交付业务结论，明确标记受影响效果和用户需要的恢复动作。不得把“独立工作可以继续”理解为可以无限改参数重试，也不得换用未登记的同类接口猜测。

伤害数值必须先区分固定数值和攻击力百分比：不要把同类 JSON 中的 `data=[1,p]` 直接当作 p% 攻击力。伤害 `data` 的权威编码由项目规则给出（Host 注入的 `damageEncodingRulePath`，必要时结合 `moduleEditorSkillPath`）：先按该规则读取并引用它，只有该规则未覆盖当前语义、或与其它项目资料、客户端证据冲突时，才派发一次只读服务器 Worker 在当前远端 HEAD 核实数据函数、参数顺序与尾字段。规则已覆盖时不得再要求服务器回执，也不得把已有的项目权威规则降级为 `uncertain`。

Host 已把冻结快照中唯一的 `combat-skill-configuration` 总控 Skill 路径注入当前战斗任务，正文由你按该路径读取；同一次注入还给出 `moduleEditorSkillPath`、`damageEncodingRulePath`、`unityAgentsPath` 与 `legacyModuleProtocolCodecPath` 四条本项目文件的绝对路径与读取命令，它们是本项目**唯一允许读取**的项目文件，必须优先用原生文件读取工具（read）读取——它按 UTF-8 解码，不会把 CJK 正文读成乱码；仅当原生工具不可用时才改用注入的读取命令，且必须逐字复制（已带 `-Encoding UTF8`，不得删改编码参数）。**编码守卫**：任何参考读取只要返回乱码或替换字符（mojibake），该次内容一律视为**未读到**，不得解释、摘录或据此下结论，必须改用原生工具重读；“乱码但大意可读”不成立。除此之外不得读取项目、用户目录、插件快照或其它位置的任何 `SKILL.md`，不得枚举 `.agents/skills/**`，也不得通过 `ghost_info`、Skill 列表或项目元数据再发现辅助 Skill。流程、权限和证据顺序由总控 Skill 给出；域事实（模块字段、编码、类型字典、伤害规则）由上述项目参考资料给出；Unity 连接统一使用 Meka Unity 官方 CLI。
