# SAGA2 服务器参考项目

在 SAGA2 中，“服务器”指 `saga2-server` 远程项目工作面，不指 SSH 主机、本地目录或当前 Unity 工程。它与客户端、设计、表格和项目管理一样，都是完整项目的一部分。

## 默认访问方式

用户询问“你能访问服务器吗”时，第一步直接调用 `mcp_router.list_remote_directory` 读取仓库根
目录，并根据真实结果回答。具体代码读取使用 `mcp_router.read_remote_file`，查找实现使用
`mcp_router.search_remote_files`。这些工具会在同一次调用内自动恢复已保存登录、复用实例，或
从唯一匹配的 SAGA2 服务器模板创建并绑定实例；不要先调用 ensure，不要先回答“不能访问”，
不要先让用户配置，也不要先创建 Worker。远程项目应像本地参考目录一样参与搜索、Git 证据和
结论整合。

默认顺序：

1. 读取本地模块、表格、导出和客户端消费者，形成已知能力矩阵。
2. 通过目录、文件和搜索只读工具核对服务器实现和当前 HEAD。
3. 把本地与远程证据合并，判断“直接支持 / 可组合支持 / 仍需核查 / 未知”。
4. 只有明确需要远端命令、持续上下文、独立历史或异步回传而直接只读能力无法覆盖时，才升级为带明确范围的 MCPR Agent/Worker；只读工具成功时禁止升级。

只有自动确保返回 `fallbackUserAction` 时，才向用户说明无法自动完成的最小原因与动作；不要追加通用“设置 → Meka 助理”提示。服务器远程项目仍不可用时，只把依赖服务器证据的调用标为暂不可用；本地设计、表格、Unity 和 P4 工作继续。

## 权限边界

远程项目只读参考不授予服务器写入。服务器文件修改、分支、提交、推送、服务启停、部署和发布属于服务器程序流程，需要专用能力和独立风险确认。战斗开发方案的实施面仍限于用户批准的模块、Timeline、表格/导出和客户端代码。

如果服务器代码证据显示能力不足或证据不确定，报告具体原子能力、代码证据和程序交接建议；不要把整个技能或整个项目判定为不可用。
