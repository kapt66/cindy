## 1. 它是什么

「远程工作区」挂在 Meka 助理分类下，但**不是第二条产品线**：用户从 Cindy 开的仍是一个普通
任务，只是它跑在 **PSB 远端客户端机器上的某个工作区目录**里。PSB 负责工作区与占用、会话记录、
字节流转发（agent-tunnel）和串流中继；Cindy 负责选择、占用、隧道客户端与观看端。用户不需要
在那台机器上手动操作，也不需要先在本地准备检出与环境。

与 [MCPRouter 远程项目会话](mcpr-remote-project-sessions.md)的区别在「远端是什么」：MCPR 是
账号下的一个远程项目实例，远程工作区是 PSB 管理的一台**客户端机器 + 它的工作区目录**，
同一台机器上可以并存多个工作区，工作区之间有 PSB 的协作锁。

## 2. 用户流程

### 2.1 左侧入口与会话列表

「Meka 助理」分类下**最上面**是「远程工作区」节点（排在 Meka 项目之前），段头右上角是
「＋ 新建任务」。段内列出**当前 Cindy 身份在本机开过的远程工作区会话**，行上给三类信号：

- **图标按钮**：用系统浏览器打开该会话所在工作区的 PSB 网页（工作区页 / 会话页签）。地址由
  PSB 下发，Cindy 只按当前生效的站点根纠正域名（见 §4），不在渲染层拼站点路径。
- **状态标签**：在线 / 离线 / 使用中 / 准备中 / 失败 / 不支持 Agent。口径由**是否被他人占用、
  机器是否在线、工作区状态**共同决定，不由会话行自己猜。
- **锁**：Tip 显示占用人名字（自己占用时追加「（你）」，如 `张三（你）`；PSB 在 `byMe:true` 时也会
  回自己的名字）；PSB 没给名字时回退「你已占用」/「他人占用」。锁是「人 vs 人」的独占反馈，不是
  「会话 vs 会话」：自己占用的工作区可以再开第二条会话。

远程工作区会话不从「全部任务」的普通项目 / 对话段重复出现，也不进 Meka 项目分组；它只在
这个节点下出现（同一个会话只有一个归属位置）。

### 2.2 新建任务：只选工作区，或当场建一个

「新建任务」打开弹窗，两个页签：「选择工作区」与「新建工作区」。**弹窗里不选引擎（Harness）**——
引擎与模型和我们平时的本地任务一样，在**会话草稿页**里选（见 §2.3）。

- **选择工作区**：列出当前身份可用的工作区（名称、所属客户端、状态标签、锁）。被**他人**占用
  的工作区仍然出现，但明确标为不可用且不能选中（理由显示占用人）；机器离线、工作区非 `ready`、
  客户端不支持 Agent 的行同样出现但禁用并给出原因——用户需要看到「为什么这台不能用」，而不是
  列表里凭空少一行。
- **新建工作区**：先选客户端（离线的机器列出但不可选中），再选项目模板（与 PSB 网页
  「新建工作区」弹窗同一份数据），可填标题。提交后弹窗保持打开、按钮禁用并显示进度；
  工作区处于 `provisioning` 时列表行显示「准备中」，要等它变成 `ready` 才能开会话。
  新建失败时给出可重试的错误，原选择不丢。
- **选定即占用（一律先确认）**：选一个工作区就是把 PSB 的协作锁占用为当前身份（与网页「协作锁」
  是同一把锁，任一侧占用另一侧立刻可见）。**任何占用都必须由用户通过确认弹窗明确同意**
  （2026-11-27 人工复测口径：禁止默认 / 自动占用）：无人占用时先弹一次占用确认，确认并占用成功
  才进入 Cindy 草稿页（按占用状态区分的选择流程见 §2.3）；取消 = 不占用、不进入草稿。
- **占用失败不留在草稿里**：别人刚抢走时提示「这个工作区正被『某人』占用」并刷新列表，**不**进入
  一个注定发不出消息的草稿。

**PSB 会话记录在首条消息发送时才创建**（那时引擎已经选定，见 §2.3）。这样弹窗只负责"工作区"这一件
事，用户不需要在工作区还没落笔之前就先决定用哪个 Harness。

会话标题只用于 PSB 侧展示（与网页会话页签同表），真正的任务名由 Cindy 自己的会话行决定。

### 2.3 草稿页：多一个「远程工作区」位置渠道（复用既有布局）

草稿页**保持现有样子**，只多一个位置渠道：位置菜单里在「本机 / MCPR远程 / 设备…」之外增加
「远程工作区」。选中它之后，右侧**项目胶囊变成工作区下拉**——列出当前身份可选的工作区
（与弹窗同一份数据，带在线/占用/不可用原因，不可用项禁选），末尾是「新建远程工作区」入口
（复用新建工作区表单，建好后自动选中）。**选中工作区 = 占用同一把协作锁**；无人占用时先确认
（见下文选择流程），占用失败（别人刚抢走）时给出可读错误且不选中，草稿仍停在原页面。

不新造顶部信息头、不新增第二个胶囊、不改 CINDY logo 与输入框位置：远程工作区是「又一个位置」，
不是「另一种页面」。

**实例标签（草稿页项目胶囊 / 选择工作区弹窗行 / 下拉主标题 / 管理页页头）一律显示工作区实例自己的
名称 = 目录名**（PSB 的 `directoryName`，如 `saga2_project-3`；2026-11-27 人工复测口径，取代 2026-11-26
的「显示工作区标题 `title`」）。用户原话：「工作区实例的显示名应该是工作区自己的名称，不是模板名」——
同一个模板（`saga2_project`）可以建出多个工作区，拿模板名当主标签会让它们看起来一模一样。**模板名
只是模板、不是实例名**；`title` 只在目录名缺失（老数据 / PSB 还没回填标题 / 手改脏数据）时回退，再
兜底 `<客户端名>-<短 id>`（`打包机-9c747178`）、短 id。**次要行只一行**：列表行固定为
**模板名 · 机器名**（去重、单行、中性 `' · '` 连接；两者都是 PSB 事实，不进翻译；与主标签重复的值
不再写第二遍）。主标签已是目录名，所以**不再显示「目录：<同一个目录名>」**（旧 i18n key
`remoteWorkspace.dialog.directorySecondary` 因此不再被引用）；没有名称时也不拿模板名顶替主标签。
状态徽标固定在行最右，不挤占标题宽度。同名工作区跨机器时主标题会相同，区分交给次要行的机器名；
**同名同目录消歧**（2026-11-26 独立审查保留）：主标题与次要行都撞时，冲突行主标题追加 `-<短 id>`
（仍撞则完整 id），保证列表里每一行可区分——选错工作区的代价是占用与会话落进别人的工作区记录。
管理页页头同口径：主标题 = 目录名（缺失回退 `title`），第二段 = `templateTitle · clientName`（去重），
不再有独立目录段。

**选择器两个入口共用一份实现**（2026-11-26 独立审查）：侧栏弹窗（`RemoteWorkspacePickerDialog`）
与草稿页项目胶囊下拉（`PsbWorkspacePicker`）只保留容器壳；「列出 → 占用 → 占用失败刷新列表补
占用人名 → hydrate VCS 通知 → 内联错误」由 `usePsbWorkspaceSelection()` 统一，行 UI / 状态徽标 /
键盘与 ARIA 由 `PsbWorkspaceRow` + `WorkspaceStatusBadge` + `usePsbWorkspaceListKeyboard` 共用：

- **一行只表达一次占用**：徽标给短标签（在线 / 使用中 / 离线…），占用人名与下一步动作（「请对方
  释放，或到 PSB 网页解除占用」）只进行 tooltip；`mine` 保留亮锁（徽标没说「是我持有」），`other`
  **不再**额外挂锁 —— 旧实现同一占用在一行里出现「徽标 + 长句 + 锁」三遍。
- **忙时也有出口**：占用请求 20s 超时（`PSB_OCCUPY_TIMEOUT_MS`），超时给可行动失败（「连不上
  PSB，请检查网络后重试」）；弹窗在途时允许取消 / 关闭，下拉卸载即放弃。**取消或超时之后才落地
  的占用会被立刻释放并记账**（占用无 TTL，不能留一把界面看不见、也没有主人接着用的锁）。
- **键盘与 ARIA**：两个入口都是 `listbox`（2026-11-27 起；Home/End、roving tabindex 只留一个
  Tab 停点；方向键只移动焦点，Enter/Space 或点击才激活选择，避免键盘浏览时反复弹确认框 / 触发
  占用）；不可用行原生 `disabled`，Tab 跳过且不进入键盘序列。
- **忙不丢焦点**：在途按钮用 `aria-disabled` + loading 而不是原生 `disabled`，开始占用的那一刻
  焦点不会掉回 body。
- **失败文案单源**：渲染层只有根 `psbFailureText.ts` 一份实现（共享码表 + `ipcError.<CODE>` 兜底、
  剥掉 `[CODE] ` 机器前缀、占用空人名回落无名字的同一句）；弹窗与下拉都指向它。
- **VCS 通知与通用错误互斥**：旧版 409 的版本控制通知在场时不再叠加通用失败条（同一事实一句话）。
- **交接值校验**：路由 history state 里的 `directoryName` 必须是单个目录名（拒 `/`、`\`、`..`、
  控制字符与超长值），脏值只丢弃该展示字段，虚拟工作目录退回工作区 id。

**选择流程按占用状态分三种（无人占用 / 我占用 / 他人占用），点击行不再等于立刻占用**（2026-11-27
用户复测）：

- **行状态**：在线 / 离线；在线行再分「**无人占用** / **我占用** / **他人占用**」（徽标与 tooltip
  见上条），其中只有前两种可选。
- **我占用 → 直接可选**：点行只把这一行标为选中，不再发占用请求、不弹确认（锁本来就是我的，
  重占一次没有意义）。
- **无人占用 → 先确认占用**：点行先复用全局确认弹窗（`useConfirmDialog`）问一次，标题带工作区
  名称、正文说明「占用后其他人无法使用，直到你释放或结束任务」；**用户确认并占用成功才算选中**；
  **取消 = 不占用、不选中**，界面停在原状态（先前的选择按 §2.5 的归还规则处理），不发占用请求。
- **他人占用 / 离线（以及未就绪、不支持 Agent）→ 不可选**：行是原生 `disabled`（点击无效、
  Tab 跳过），徽标给短状态，占用人名与下一步动作（请对方释放 / 到 PSB 网页解除占用）只进
  tooltip；不做「点一下再报错」。
- **两个入口同一流程**：弹窗与草稿页下拉都走 `usePsbWorkspaceSelection` 的
  `requestSelect → confirmOccupy / cancelOccupy → handoffSelection`。**弹窗**在行上确认并占用
  成功后只把该行标为选中，**主按钮「新建任务」才交接**已占用的工作区（不第二次占用）；**下拉**
  确认占用成功即交接给草稿。占用确认文案为
  `remoteWorkspace.dialog.confirmOccupy.{title,body,confirm,cancel,occupying}`（12 locale 同步）。

**远程工作区草稿不借用「另一台电脑上的模型」与「本机引用目录」**（2026-11-26 独立审查修复）：
psb 目标在首条消息懒建会话之前没有 `remoteHostId`，模型选择器里「另一台电脑上的模型」一旦被选中，
`patchDraft({ agentDeviceId })` 会把 `psbTarget` 静默清掉（换设备 = 换目标）；同理「控制端本地
引用目录」经 `createSession` 的 `extraDirs` 带到远端是无效路径（远端没有这些目录，甚至报错）。
所以草稿页按 `isPsbDraft || isPsbChannelSelected` 同时收掉这两面（与 device-link / SSH 同口径），
**不**靠伪造 `remoteHostId` 来挡。位置渠道已选「远程工作区」但还没选工作区时，发送 / 建目标会被
拦下并给一句专用可行动提示（`remoteWorkspace.draft.selectWorkspaceFirst`，不复用页签标签
`remoteWorkspace.dialog.tabExisting`）。

**引擎与模型在草稿页选，和本地任务同一条链路**：Claude Code / Codex / Pi 三选一，模型面用本机目录
（远端只吃 AI Gateway 凭据，不复制本机 OAuth）。用户先选引擎、再发消息；**首条消息发送时**才用当时
选中的引擎创建 PSB 会话记录，并把返回的会话 id 固定成这条任务的远程身份（之后再改引擎需要新建任务——
会话的引擎在 PSB 侧已经落库）。

首条消息仍走普通新建任务的链路创建 Cindy 本地会话；远程身份是会话行上的 `psb:<PSB 会话 id>`，
工作目录只是这个工作区的**虚拟引用**（仅用于显示与选择，不参与本机路径解析、不建本机 worktree、
不解析路径型附件）。

**草稿目标只有一份判据（2026-11-26 独立审查收敛）**：位置 / 工作区 / 项目这些互相约束的草稿
状态由 `state/newMakerDraft.ts` 的 `DraftTarget` 联合 + `deriveDraftTargetFields()` 单点归约，
`resolveDraftTargetKind()` 是**所有闸门**（发送、建会话、选择器、占用释放）的唯一判据；新增目标
类别只改这一处，不允许各入口各写一遍 `isPsbDraft || ...` 组合。`explicitNoProject` **只**表示
用户显式选了「对话」，不承担其它语义；一次性导航（侧栏 / 移动端 / 深链）的三套 reader 收敛为
`NewMakerNavigationIntent` 联合的单次 consume，避免同一次导航被多处各读一遍。PSB 草稿目标的
生命周期由 `usePsbDraftTarget` 统一负责（懒建会话 / 在途拒绝 / 换目标 / 卸载释放，owner
generation 校验），路由只注入依赖。

### 2.4 会话页：输入禁用、透明重建与串流

- **输入禁用**：只有三种**外部条件**会让输入框置灰并给出一句原因——工作区被他人占用、远端客户端
  离线、工作区未就绪（消息发出去也没有接收方）。占用被释放或机器恢复后下一次刷新即可继续输入。
  **「不允许发送」覆盖所有入口**：回车/发送、附件、语音稿、快捷插话（
  composer 为空时把唯一排队消息直接发出去的那条路径）以及排队消息气泡上的「插话/编辑」都
  一起禁用——只禁用正文输入而留插话路径，等于把同样的失败换一个按钮触发。
- **PSB 会话终态不锁输入**：终态（`stopped` / `failed`）只说明这条 PSB 会话不能再开隧道，
  **本地任务并没有结束**。用户下一次发送时，主进程会在同一工作区新建一条 PSB 会话、把本地任务
  重绑过去并发起这一轮；界面不出现「这个任务已经结束」这类死路文案。措辞上不承诺恢复上下文
  （PSB 是否支持 resume 尚未确认），只说「可能不会延续」。重建失败时照实报错（例如 PSB 侧会话
  记录已不存在、无法自动重建），不静默吞掉这一轮：消息留在队列首位，错误串按 `[PSB_*] + 中文
  原因` 显示（如 `[PSB_CLIENT_OFFLINE] 远端客户端当前离线，暂时不能发消息。`），输入仍然可用，
  下一次发送会重新尝试。
- **重建是透明的，只给一行淡提示**：重绑成功后主进程推送 `psbRemote.sessionsRebound`；会话页据此
  立刻把远端身份、输入判据与串流观看端一起切到新会话，并在 composer 上方
  显示一行**可关闭的中性提示**（「远程 Agent 已重新连接。本轮上下文可能不会延续。」）。它是
  信息不是告警：不阻塞输入、不用橙色警告条、不写进消息流，也不改变「任务还在」的事实。
  **「远程工作区」页签不跟这条重绑走**：它按工作区工作（见下），不显示任何「会话已结束」文案。
- **状态会自己刷新**：会话页每 30s 读一次 PSB 的工作区/会话状态（进入页面读一次、窗口重新聚焦
  补读、页面不可见时不发请求）；**侧栏列表是另一条链路，节流为 12s**（`REFRESH_TTL_MS = 12_000`，
  与聚焦补拉配合）。用户不需要手动刷新就能看到「占用被释放」「机器恢复在线」；读取失败时保留
  上一次已知状态，不会因为一次网络抖动就把可以输入的会话锁死。会话终态后轮询不停止：重绑会换
  会话 id，推送之外保留轮询作为第二条发现路径。
- **「远程工作区」入口与页签（2026-11-26 用户口径，替换旧的「远程管理」）**：入口是**会话标题行内、
  标题后的「…」菜单之后**的**文字按钮「远程工作区」**（`[图标][标题][…][远程工作区]` 同一行；标题
  过长时由标题自己截断，按钮固定在这一段末尾，不挤压标题、不改变标题行高度）。它**不再**挂在窗口
  右上角（`ContentHeader.trailing`），也不是内容区里的浮动图标 —— 也不再有 icon-only 的「串流」按钮。

  main 侧分发，渲染层 `preventDefault` 管不到）。允许清单是**白名单**：只有 `Escape`（退出
  全屏）、`F5` / `F11` / `F12` 与 `Ctrl+Shift+I` / `J` / `C`（macOS `Cmd+Alt+I/J/C`）留给宿主，
  让用户能退全屏 / 刷新 / 开开发者工具自救；清单唯一来源是共享契约
  `psbStreamCaptureIsPassthroughInput`（main 抑制与渲染层转发共用，不各写一份）。
  `Alt+Tab`、`Win`/`Meta`、`Ctrl+Alt+Del`、`Ctrl+Shift+Esc` 由操作系统先处理，
  全屏下 `Esc` 由浏览器占用（退出全屏）——这些网页拿不到，界面不假装能拦。
- **失焦 / 退出全屏 / 断连补发释放（2026-11-26）**：远端（xdotool）只认「收到过 keydown 的键
  正在按下」这一份状态，浏览器不保证补发 keyup。因此窗口失焦、`visibilitychange→hidden`、画面
  失焦、退出全屏、串流断开 / 停止、组件卸载时，一律把当前按下的键与鼠标键补成一批 `keyup` /
  `pointerup` 发出去，避免远端卡住 Alt / Ctrl / 左键（表现为「一直在旋转 / 一直在框选」）。
- **进入页面不自动启动，离开页面自动停止（2026-11-26 用户改口）**：进入「远程连接」分类时保持
  「串流未启动」空占位（HUD 若开着字段为「—」），**不会**因为
  `adminContext.desktopSession === 'running'` 或 `adminStreamStatus.active` 自动
  `adminStreamStart`；一律由用户点「启动」明确开始（启动前的 PSB 状态只用于按钮可用性与空态
  提示）。页签不可见（切到别的页签 / 收起右侧栏 / 切到别的分类）时**仍然自动**
  `adminStreamStop` 释放观看名额；回到页面是未启动态，需要用户再点「启动」。判据用**既有 tab
  pane 可见性**（`active && shellVisible`），不用 `document.visibilityState`（它只反映窗口，
  后台页签仍是 visible）。启动 / 停止进行中不重复发请求。
- **打开页签不订阅、不创建会话、不占用工作区（2026-11-26 审查修正 + 0.1.172 服务接口）**：
  「读状态」只用**观看端绑定**里的会话 id（内存绑定 / 本机记录里的 `desktopSessions`）发一次只读
  HTTP；**不会**为了读状态去订阅（订阅占观看名额）、也**不会**新建 PSB 会话（新建会话属于工作区
  写操作，会顺带把空闲工作区占用到自己名下）。因此：
  - 从没在这个工作区点过「启动」时，`desktopSession` 可能是未知（`null`），页面不据此禁用
    「启动」，也不猜 `none`；
  - 点过一次「启动」后本机会记下该工作区的观看端绑定会话 id（正常是 PSB 桌面访问会话 id），之后
    重启客户端 / 重开页面仍能读到状态（不会为了「恢复状态」而悄悄订阅或占用工作区）；
  - 绑定只认**本机记录**与工作区级订阅的返回值（不会按标题认领 PSB 会话列表里别人的会话）。
- **详情是浮层，不改变布局**：点「详情」在按钮下方弹 Popover，显示分辨率、PSB 下发的编码名
  （`encoder`，诊断用）、帧率、最近错误与 PSB 的 `reasonCode` / `desktopSession`；再点、Esc 或点
  外部关闭。打开 / 关闭都不改变控制条高度、不让画面位移（2026-11-26 用户口径，替换旧的
  「详情内联展开」）。
- **串流观看端照实转述 PSB 的结局**：PSB 拒绝或关掉订阅时，面板显示它给的原话（如「这个 agent
  会话已经结束…」「没有可观看的画面」）；这是观看端的真实状态，不用它推断「任务结束」。按
  `reasonCode` 的专用引导（没有桌面会话 / 桌面正在起 / 客户端不支持串流）在本页的空态里给出。
- **「已连接」与「有画面」分开说（2026-11-26 口径，独立审查补实）**：点「启动」成功只代表本端订阅
  建立（此时「停止」可点），面板显示「已连接，等待画面…」（`remoteWorkspace.session.streamWaiting`）；
  **只有本端收到第一帧才进入「串流中」**——`streaming` 状态只由 `frame` 事件置 true。PSB 的
  `active` 是「那台机器此刻有没有采集」，**既不能**用它提前显示「串流中」（订阅成功但零帧时是错的），
  **也不能**在帧仍在到时因 `active:false` 把画面切回未启动；它只留在状态里供提示 / 详情使用。
  Cindy **不会**把它改写成 true 来假装在播（见 §6 与工程契约 §5）。
- **启动被 PSB 明确判为不支持时要给原因**：点「启动」时若刚读到的状态是 `capability:false`（按钮的
  禁用态来自上一次渲染，状态可能刚被推送刷新），不能静默 return，给
  `remoteWorkspace.session.streamUnsupported` 的可行动提示（与失败码
  `PSB_STREAM_UNAVAILABLE` 的文案同一个键，见工程契约 §4）。
- **没有画面时按「未就绪」处理，不再误报成「网络慢」**（2026-11-26 修正）：工作区没有 running
  桌面会话、或桌面会话还在起/停时，PSB 用 `4004` 关掉订阅，并在 close reason 里带结构化的
  `reasonCode` / `desktopSession`；串流中继的「慢订阅者被断开」也用 `4004`，但**只发生在已经收到过
  画面帧之后**。Cindy 的 main 按「有没有结构前缀 + 本连接是否收到过帧」归因（工程契约 §5）：
  - 未就绪（`desktopSession:"none"` / `"starting"`）→ 可恢复状态：按提示去 PSB 网页「远程控制」
    页签启动桌面会话（`none`），或等它落定后重试（`starting`），**不当作失败**；
  - 已 `running` 但暂且没有画面 → 保持订阅等首帧，不要重连；
  - 收到过帧之后的 `4004` → 才是慢订阅者/网络积压问题。
  用户可见的提示沿用 PSB 随同一份状态下发的中文原话（`lastErrorZh`、close reason 里 `|` 之后的
  那句）；机器判断按 `reasonCode`，不解析中文。按 `reasonCode` 的专用引导（`NO_DESKTOP_SESSION` /
  `CAPTURE_NOT_READY` / `CLIENT_NO_STREAMING`）已接入「远程工作区」页的空态文案。
- **`desktopSession` / `reasonCode` 的含义**（详情与空态文案共用）：`desktopSession` = 该工作区
  此刻的桌面会话状态（`none` 去网页启动 / `starting` 等待 / `running` 可能有画面）；
  `reasonCode` = 为什么没有画面（`NO_DESKTOP_SESSION` / `CAPTURE_NOT_READY` /
  `CLIENT_NO_STREAMING`；null = 没有阻塞性问题）。「详情」是**浮层**，按 2026-11-26 用户口径
  显示分辨率、PSB 下发的编码名（`encoder`）、帧率、最近错误，以及 PSB 的 `reasonCode` /
  `desktopSession` 机器字段（供排查，机器码原样显示、不解析成中文）。**编码 / 解码器名称只用于诊断，
  不提供可调编解码参数**（码率、预设、关键帧间隔等没有采集端契约，界面不摆假开关）。
- **协同（Orca）入口不提供**：远程工作区会话页不显示协同开关。远端只提供 Agent 会话的字节流
  转发，没有「在远端拉 Worker」的契约；放行入口只会把用户引到一条必失败的 SSH preflight 上。
  草稿页与会话页共用同一判定（`collabEntryPolicy`），不要只在一处隐藏。
- **占用失败要说清是谁**：选工作区被抢时提示「这个工作区正被『某人』占用」，占用人名由 PSB
  409 的 details 提供；拿不到人名时退回「使用中」，不把空名字填进句子。
- **串流是服务调用，不是用户任务（2026-11-26 用户事故后收口，PSB 0.1.172 已适配）**：PSB 的框架
  规则是**Agent 会话只装用户任务**，串流 / 工作区读取 / 访问起停走**服务接口**（与网页同一套调用，
  不产生任何会话记录）。Cindy 的观看端已改用工作区级
  `POST /api/cindy/remote/workspaces/:id/stream/subscribe` 拿**桌面访问会话** id 订阅，
  **不再创建「Cindy 观看端」内部 Agent 会话**，因此 PSB 会话列表只出现用户自己发起过的任务。
  - **没有 running 桌面访问会话时**（2026-11-26 真机事故修复）：订阅返回 409
    `details.code='NO_RUNNING_SESSION'` + `details.state` + PSB 可行动中文。Cindy 不再把它落成
    「操作失败，请稍后重试。」，而是按 `state` 给三档可行动横幅（12 locale），并把 PSB 中文原话
    作为诊断行同时显示：
    - `none` / `stopped` / `failed`：**「工作区访问没有在运行：请先在 PSB 网页打开该工作区的
      「远程控制」并启动访问；启动后再点「启动」。」** 横幅同时给**「在网页启动访问」**按钮
      （复用「在网页打开」能力：main 解析 `webUrl` 后用系统浏览器打开 PSB 网页，用户在那里点
      「启动访问」）；
    - `starting`：**「工作区访问正在启动（Unity/虚拟桌面还没就绪），请稍等再试。」** 并**自动
      重试一次**（约 2s；只一次，不循环）；
    - `stopping`：**「工作区访问正在结束，请稍等再试。」**，只说明等待，不自动重试。
    页面**不会**因为点「启动」自动拉起桌面访问（那是 PSB 网页上的显式动作），也**不会**降级去建
    会话；Cindy 侧只做一次**非致命**的「尽力拉起」尝试（见下一条与 §6 的能力边界）。
    实现位置：main `psbClient.subscribeWorkspaceStream` + `adminService.acquireBinding`；渲染层
    `psbStreamAccessFailureNotice` + `RemoteWorkspaceAdminConnection` 的失败横幅；工程细节见
    [PSB 传输契约 §11.8](../dev-rules/psb-remote-session-transport.md#118-订阅-409-no_running_session-的处置与-accessstart-入口2026-11-26-真机)。
  - **订阅前「尽力拉起访问」（可选增强，失败不阻断）**：main 在订阅前按**能力位**决定是否尝试
    PSB 通用网页接口 `POST /api/remote/workspaces/:id/access/start`（幂等 ensure）+ 轮询
    `GET /api/cindy/remote/workspaces/:id/access` 到 `running`：能力位 `open` 时前台等待；
    `closed`（Cindy 入口未开放）时本进程内跳过；`unknown` / `failed` / `timeout` 时**后台预热、
    不阻塞启动**。**当前它基本不会成功**：PSB 的 Cindy Bearer 白名单还没放行 `/api/remote/**`
    （恒 403），PSB 台账记的是「Cindy 入口下一轮加」。所以这条只是预埋能力：入口没开时照常订阅，
    由订阅的 409 给出上面的可行动文案；**不要**把它描述成「Cindy 能保证起访问」。
  - **桌面访问被重建后**：旧绑定 id 读不到时，下一次「启动」会重新订阅拿新 id（订阅是过渡形态的
    短句柄，Cindy 不把它当长期身份）。
  - **旧 PSB 的过渡回退（仅临时）**：只有订阅端点不存在（404/405/`UNSUPPORTED`）时，才允许创建
    一条**内部 Agent 会话**充当观看端，且必须显式 `purpose:'internal'`（PSB 默认不列进会话列表、
    不增加工作区 `sessionCount`）+ 标题写明「内部串流订阅」+ warn 日志。这是灰度期的止血，不是
    产品方案；新端点可用时永不触发，灰度面收窄后删除。工程细节见工程契约 §11.7，跨仓事实见
    [跨仓契约摘要](../collaboration/psb-remote-workspace-contract.md) §1.3 / §1.6 / §3.2。

### 2.5 占用什么时候释放

占用不是心跳租约，本轮没有自动过期（PSB 若要加 TTL 需双侧同时改）。显式释放只发生在：结束会话、
放弃草稿、以及**这次选择没能进草稿**（2026-11-26 复审补充：picker 已占用成功，但发送 / 目录恢复
在途让换工作区被拒绝时，草稿页立刻把刚占用的工作区还回去，并给一句「正在发送，结束后再选」的
提示；重选当前正在用的工作区不释放）。**退出登录不释放**，也没有 TTL / 后台回收：进程被强杀或换
账号后占用仍留在原身份名下，用户需要到 PSB 网页手动解锁；Cindy 下次刷新列表时看到解锁（`dispose`
只断开串流、不调用 `releaseWorkspace`），不要写成「退出登录释放」。正常应用退出与任务结束走下面
的主动释放。

**选择器里选过但还没交接的占用**（2026-11-27 用户复测）：只有「**本次选择期间由选择器新占用、
且还没交接**」的工作区在放弃选择时归还——切换选择、关闭弹窗、下拉卸载都走同一条清理，
**每次选择至多归还一次**（先清登记再发释放，重复清理不会重复释放）；归还失败进工作区级待释放
账本（见下）。**选之前就已是 mine 的锁不归还**（可能是同一用户另一条任务占的，替它释放会打断
那条任务）；**交接给草稿 / 任务之后不再归还**，释放交给草稿 / 任务生命周期（离开草稿、任务结束）。

**任务结束时释放占用（2026-11-26 用户要求；2026-11-27 收敛为 main 单权威）**：

- **main 是唯一权威**：`maker-host/psb-workspace-session-release.ts` 幂等、可重试、不阻断——先读
  PSB 会话行，只有「由我占用」才 `releaseWorkspace`（PSB 侧幂等）；未占用 / 别人占用成功 no-op；
  失败（网络 / 鉴权 / 5xx）记进**有界进程内账本**（同一 `(sessionId, reason)` 只留一条），
  供之后重试。**归档 / 删除的释放由 main 的终态 observer 发起**，渲染层不再对同一次动作重复
  上报：`features/cc-agent/psbOccupancyRelease.ts` 降为**旧 main / 旧 preload 的兼容账本**
  （能力探测到新 main 已拥有终态释放时零调用、不写本地账本），同一动作只产生一轮 PSB 请求。
- **同一个工作区还有别的活动远程任务时不释放**：归档其中一条只是「这条任务结束」，不是
  「工作区结束」——main 发现同工作区仍有 `status='active'` 的 `psb:` 任务就**跳过释放且不入账**
  （`workspace-in-use`），避免把别人（或自己的另一条任务）正在用的工作区提前解锁给他人抢走；
  判断所需的活动任务列表读不到时，同样保守按「在用」处理，不提前解锁。
- **触发点**：任务进入终态（`localDb/ipc/sessions.ts` 的终态 observer，覆盖批量归档 / 元数据
  patch / 侧删 / 解绑）、应用退出（`bootstrap-electron.ts` 的
  `onQuit('psb-workspace-session-end-release', …, 'async')`，在 `installQuitHandler(16000)` 之前
  注册：并行释放全部活动 `psb:` 任务占用 + 两种作用域的隧道 + 待释放账本重试；预算 **16s**
  （`runQuitDisposers` 的 async 阶段并发执行、整体超时），超时不阻塞退出，失败只 `warn`）。
- **不在普通 runtime close 上释放**：`/clear`、换模型、工作目录漂移回收都会 close runtime，
  但那不是任务结束，提前释放会让协作锁在用户还在用时被别人拿走。
- **失败账本与重试**：账本条目带失败时已读到的 `workspaceId`，重试优先按它直接释放工作区——
  不依赖 PSB 会话行还在（会话 404 时锁仍可归还），也不再为一条账本各打一次状态查询；会话 /
  工作区已不存在、已被他人占用属于**终止归因**，直接出账不再重试。**重试前还要复核两件事**
  （2026-11-27 终局复审）：① 这条任务是否**又被恢复成活动任务**——`active` 时只出账，不释放
  锁、也不收隧道（锁正被恢复的任务合法占用；读不到活动列表则保留条目）；② 同工作区是否还有
  别的活动任务——只有确定结论才出账，`unknown`（读不到本机映射且读会话行也失败）**保留条目**，
  不把「无法确认在用」当成「别人在用」把待释放义务静默丢掉。条目带当前账号印记：
  **切号后不替旧账号归还**，账号边界清空账本。渲染层只缓存 main 的快照（启动读一次 +
  订阅 `PENDING_RELEASES_CHANGED` 推送 + 用户显式点重试）。
- **两套账本分工（不要合并）**：会话结束释放的失败提示 / 重试读的是 **main 账本**
  （`pending-releases:get` / `pending-releases:retry`）；渲染层
  `draft/psbPendingReleaseLedger.ts` 只覆盖 **picker 放弃草稿 / 在途取消** 时渲染层直接调
  `releaseWorkspace` 的**工作区级**失败（key = workspaceId）。两者 key 空间不同（会话级 vs
  工作区级），**存储与重试仍各自独立**；但提示条**展示时按 `workspaceId` 跨源去重**：同一把
  工作区锁只出现一条（main 条目优先、作为会话结束释放的权威覆盖工作区级副本；main 内部同一
  工作区只留最近失败的那条；读不到 `workspaceId` 的 main 条目无法对齐，按来源 key 保留）。
- **常驻提示条（2026-11-27）**：主窗右下角一条**非阻塞**提示（不弹模态、不遮输入）：计数徽标 +
  最多 3 条失败原因（余下折成「+N」）＋「重试」/「关闭」。「重试」是**唯一**入口：先重试 main
  账本，再重试**未被 main 覆盖**的工作区级条目（同一工作区两本账并存时由 main 代表，避免对同一
  把锁打两次；旧 preload 缺 main 方法时两本账各自重试），不排后台重试；「关闭」只隐藏**当前这
  一批**（账本仍在，新的失败会重新出现）；重试后仍失败时正文换成「占用可能仍未解除」
  （`remoteWorkspace.draft.releaseRetained`）。原因行文案按共享单表归一：main 账本的 PSB 原始
  失败码先经 `psbFailureDescriptorForPsbCode` 映射成文案键，已知失败不会落成 PSB 原文；归一不
  了的码保留原文。副窗 / 侧栏窗不渲染；旧 preload / 无 bridge 时降级成「没有提示」而不是报错。
  带数量的汇总文案键留给 i18n Wave 2，当前用计数徽标表达 N。
- **接线状态**：main 端口、IPC channel / preload 桥（`releaseWorkspaceForSession` /
  `pendingWorkspaceReleases` / `retryPendingWorkspaceReleases` /
  `onPendingWorkspaceReleasesChanged`）、渲染层兼容账本与常驻提示条均已实现，有定向单测与源级
  守卫；真机端到端仍未验证（§8.2）。

**再次交接同一个工作区不产生第二条 PSB 会话**：侧栏再点一次「新建任务」选同一台工作区时，草稿沿用
已懒建的 `sessionId`（不覆盖成 `null`），否则旧 PSB 会话会变孤儿、下次发送才会再建一条。

**在途占用 / 建会话的两种「没有主人」的残留都要收掉**（2026-11-26 独立审查）：

- **占用在途取消 / 超时 / 弹窗关闭 / 下拉卸载**：占用请求可能已经在 PSB 生效，而界面已经不再
  要这个结果。此时渲染层会立刻 `releaseWorkspace` 把锁还回去；还失败就进「待释放账本」
  （`renderer/features/remote-workspace/draft/psbPendingReleaseLedger.ts`，`PSB_PENDING_RELEASE_NOTICE_KEY`
  为给用户的提示文案键），由常驻提示条统一展示与重试（见上）。放弃草稿时 stop 超时后仍尝试 release，
  release 失败同样入账——不再只写一行 `log.warn` 让用户以为锁已经没了。
- **PSB 会话建出但草稿没有采纳**（等待期间目标被换掉 / 提交竞态）：gate 会尽力 `stopSession`，
  并**保留本次去重键**；用户重试时 PSB 按同一 `clientRequestId` 拿回同一条会话，不会再多建一条
  （此前旧实现先清键再静默 return，重试会建出第二条、远端的旧会话则永久孤儿）。

**工作区被交接给别人后**：任务本身不中断，但 Cindy 不会继续「以为锁还是我的」——**下一条消息
发送前会重新校验**：仍由我占用 → 正常发送；已被交接回无人占用 → **不自动占用**，弹「需要占用这个
工作区」确认框，用户确认并占用成功后**自动重试这一条发送**（取消则这条不发送、草稿保留）；已被
他人占用 → **这条消息不发送**，输入框按「被他人占用」提示占用人名字与下一步（请对方释放，或到
PSB 网页解除占用后重试），消息保留在输入框 / 队列里可重试。校验读不到 PSB（网络 / 鉴权）时同样
**不发送**并如实报错，不把「无法确认」当成「可以写」（见 §2.6）。

会话终态后的**透明重建不改变占用**：新 PSB 会话仍落在同一工作区；如果这时占用还在自己名下就
沿用，若占用已被释放则按 §2.6 由用户确认占用后再继续（重建同样是写入，见 §2.6）。反过来说，被他人
占用时输入仍置灰（§2.4 的第一种阻断），此时不发消息，自然不会触发重建。

### 2.6 写前锁定（占用闸门，2026-11-26；2026-11-27 复测改「一律用户确认」）

PSB 服务端对工作区的**写操作**（新建会话、启动串流、发送消息）要求「这个工作区由自己占用」。
Cindy 在这些入口**再自己确认一次**，不把 PSB 的拒绝直接抛给用户：

- **已由自己占用** → 直接继续。
- **还没有人占用** → **不自动占用**（2026-11-27 人工复测：所有工作区占用都必须由用户通过弹窗
  确认，禁止任何默认 / 自动占用）。Cindy 弹「需要占用这个工作区」确认框（标题带工作区名，正文
  说明「占用后其他人无法使用，直到你释放 / 结束任务」）；**用户确认并占用成功后，Cindy 自动重试
  刚才那次动作**（发送 / 启动串流 / 新建会话），用户不需要再点一次；**取消 = 不占用、不执行该动作**
  （发送的草稿 / 附件保留，串流不启动，会话不创建）。
- **被别人占用** → 动作被拒绝，说清占用人是谁与下一步（请对方释放，或到 PSB 网页解除占用后重试）。
  三种入口一致：新建会话**不创建**、串流**不建立订阅**、消息**不丢**（留在输入框/队列里可重试）。
- **客户端离线 / 工作区未就绪或已不可见** → 给对应原因，不做占用询问（占用了也用不了）。
- **网络或鉴权失败** → 照实报（连不上 / 需要重新登录 / 需要企业组织），不伪装成「被占用」。

**确认弹窗与 PSB 守卫契约同码**：空闲工作区在 Cindy 侧由占用闸门返回「还没占用」
（`PSB_WORKSPACE_NOT_OCCUPIED`），与 PSB 2026-11-27 对「新建 / 继续 Agent 会话」的
`403 WORKSPACE_NOT_OCCUPIED` 是同一个语义；PSB 上线后用户看到的流程不变。**释放占用**时若该
工作区里还有会话正在输出（PSB `409 AGENT_SESSION_ACTIVE`），提示「先结束或停止这个任务，再释放
占用」，**不**自动重试、**不**引导用户去 PSB 网页绕开契约。

**占用失败不留半截**：用户确认后占用仍失败（被抢 / 离线 / 网络）时，刚发起的动作**不重试**，
按真实原因给可行动失败；确认框只弹一次（不会为了重试再弹）。

**发送消息的校验是「每一条」而不是「会话创建时」**（2026-11-27 人工复测收口）：会话创建后工作区
仍可能被交接给别人，所以 Cindy **不靠本地缓存 / 上一次的检查结果**放行——每条消息发送前都重新
确认一次当前占用。读不到 PSB 或鉴权失败时这条消息**不发送**（如实报错、可重试），
**不会 fail-open 继续写**。这条校验只作用于 `psb:` 远程工作区任务；本机 / 其它远端任务不经过它，
**不发任何 PSB 请求**。

串流**启动**要锁定；启动之后已经建立的键鼠输入不单独再校验（启动那次已经锁过；未锁定场景由启动
失败覆盖，不会出现「输入悄悄丢失」）。**只读动作不在闸门内**：打开「远程工作区」页签、读
`adminContext` / `adminStreamStatus` / 刷新列表都只是读，**不占用工作区、也不创建 PSB 会话**
（2026-11-26 审查修正：读路径建会话会把「看一眼页面」变成一次静默占用）。

### 2.7 占用 / 释放时的版本控制检查提示（CINDY-RW-10，2026-11-26）

PSB 在**占用 / 解除占用的那一刻**检查工作区检出是否干净（P4 会执行 `p4 reconcile`，避免新增文件
未 add、修改文件未 open）。产品口径以 2026-11-26 20:4x 再更正为准：

- **占用 / 解除占用本身照常成功**（除非权限、被他人占用、工作区不存在等原有错误）。检查结果是一份
  **建议**，不是拦住操作的错误：成功响应里带 `data.vcs`（`dirty:true` 才有），Cindy 显示**非阻塞
  提示**（页头 / 横幅 / 页内条，不遮断输入），文案直接用 PSB 的 `messageZh`。
- 提示里给用户两个选择：**「查看详情」**（`inspect-vcs`，按服务端 action 拉未提交修改明细）与
  **「一键清理」**（`clean-workspace`）；另有 **「继续」** = 忽略提示、关闭它，**不发任何请求**。
- **清理是不可逆操作**：会删除新增文件、还原已修改文件、Git 检出切回默认分支（PSB 在
  `descriptionZh` 里会写清楚）。Cindy 必须先二次确认（列 projects / changes），确认后按 **kind
  决定固定 method + path**（path 由本地用 `encodeURIComponent(workspaceId)` 拼），**不采信服务端
  下发的 method/path**：服务端形状只用于确认这是一条已知 action，不一致就整条丢弃
  （工程契约 §13.5 / §15.2）。
- 清理是**异步**的（服务端 202 + `operationId`）：Cindy 显示「清理已开始」并给「刷新」按钮；**不猜
  轮询端点**（服务端没给就不新增未约定请求）。刷新复用既有的工作区列表读取。
- **旧版 PSB（<0.1.180）兼容**：仍可能返回 `409 WORKSPACE_VCS_*`。这时操作没有生效，按错误处置：
  `retry` / 旧 `revert-*`（同样二次确认）。旧 `force-release`（忽略修改强制释放）**已删除**：
  Cindy 不提供、不渲染、不执行。
- **没有「force」分支**：不能以「忽略检查」越过；用户只能清理、重试或继续使用。
- 覆盖入口：工作区选择弹窗 / 草稿页选择（选中即占用）、管理页页头占用 / 解除占用、发送前占用闸门、
  启动串流与新建会话的占用闸门。**用户确认后显式占用**（`workspaceLock` 的 occupy 端口，
  operation=`ensure`）产生的提示同样要出现，不能因为「不是用户点占用按钮那一下」就静默吞掉。
- **展示位置（Cindy，2026-11-26 接线）**：Cindy 在三处展示 advisory 与清理入口 ——
  ① **主窗口全局横幅**：把同一份通知盖到所有入口（含发送前确认后占用、放弃草稿释放这类没有稳定
  UI 落点的路径），所以**首条消息发送失败 / 释放失败**也有提示与清理入口，不额外弹模态；
  ② **「远程工作区」管理页 › 版本控制分类**的页内条（没有通知时仍是原占位空态；页头占用 /
  解除占用成功后会兜底读一次，切到该分类即可看到刚产生的建议）；
  ③ **选择工作区弹窗 / 草稿页工作区下拉**里的页内条：占用失败（旧版 409）时就在原地展示，
  用户不用离开当前上下文去找清理入口。三处都是非阻塞的（不遮断输入、不弹模态；清理的二次确认
  除外），「继续」只关闭提示。
- **放弃草稿 / 换目标时的释放失败**：不阻塞离开，但**不能静默**：给非阻塞提示 + 常驻提示条（用户
  需要知道远端占用可能还在），见 §2.5。

**最终呈现形态（2026-11-26 独立审查 r4，实现事实）**：

- **主窗口横幅固定在右下角悬浮**：避开右上角窗口按钮 / 标题行拖拽区与仓库 ToastContainer 的落点；
  `pointer-events-none` 容器 + 内层 `pointer-events-auto`，不遮断输入；横幅带**工作区名**。
- **同一时刻显示「最近一条」**：每条通知带单调递增 `revision`，多工作区同时有提示时取 revision
  最大者；兜底读与推送按**单调合并**——请求期间该工作区已有更新的推送 / 清除时，以本地为准，
  不覆盖也不清除。
- **关闭语义按类型区分**：「继续」= advisory 直接关本地（建议随时可忽略）；非 advisory（旧版 409）
  先调 main 的 `continue` **清掉有界缓存**再关，否则下一次兜底读又会把提示带回来。
- **二次确认文案按 kind 并列 projects / changes**；「清理已开始」只属于 `clean-workspace`（202
  异步），其它 kind 不显示。
- **stale / 占位身份只读**：读不到工作区时不给写动作入口；VCS 提示与通用错误互斥，同一条失败只
  出现一处，不叠两条 toast。

工程细节（IPC、缓存、安全校验、action 白名单）见工程契约 §13.5；跨仓事实见
[跨仓契约摘要](../collaboration/psb-remote-workspace-contract.md) §2 `CINDY-RW-10`。

## 3. 鉴权口径

远程工作区的所有 PSB 调用（HTTP 与两条 WebSocket）都用**宿主直签的 Cindy Connection JWT**：

- 走的是与「Meka 提交」「项目管理」**同一条 OIDC 链路**，不新起一套鉴权、不新增 audience：
  audience 复用现网值 `<orgSlug>:meka-submit`。改名不是纯客户端改动——PSB 部署配置
  （`CINDY_AUTH_AUDIENCE`）必须同时改，否则全部调用 401。
- 只有**企业组织成员**可用：个人 membership 没有 `orgSlug`，签不出 audience，界面直接说明
  「需要企业组织」，不去猜一个 `personal:` audience。
- token **只在主进程内存缓存**：不落盘、不进渲染层、不进 IPC 返回值、不进日志。渲染层能看到
  的身份信息只有「当前 PSB 站点根 + 是否测试部署」。
- PSB 侧按既有 `packages/cindy-auth` 验签，并把 `sub` / `email` 映射到同一行 `people`；调用路径
  限定在 `/api/cindy/remote/**` 的精确形状白名单内（不放宽成 `/api/cindy/` 宽前缀）。

## 4. 端点与切换

| 环境 | 站点根 | 用途 |

| 正式 | `https://mekabot.meka.pawdy.fun` | 默认（生产） |

切换方式**复用既有机制，不新增开关**：启动期环境变量 `CINDY_MEKA_PSB_HOST`（取值白名单只认

解释的分裂。机制细节（白名单取值、启动命令、日志）以
[插件安全与作者契约 §4.4](../dev-rules/plugin-security-and-authoring.md) 为准。

两条 WebSocket 一律 `wss:`，**不做明文降级**：把带 Bearer 的隧道降到 `http`/`ws` 会让 token 与
会话内容出现在链路上。PSB 下发的绝对网页地址会按当前生效的站点根只替换「协议 + 主机」，路径
保持 PSB 的事实，避免联调时点开链接跳到生产。

## 6. 能力边界与已知限制

- **串流可交互；输入的授权由 PSB 权限模型判定（2026-11-26，0.1.172 口径）**：Cindy 的「远程工作区」
  页**默认允许交互**——订阅建立后把指针 / 键盘 / 滚轮经**工作区级**
  `adminStreamInput({ workspaceId, event })` 发到同一条观看端 WS，全屏时独占键鼠（允许清单除外）。
  PSB 已**取消** `role=control` 单控制者 / `takeover` 互斥，改为服务端权限模型：工作区被占用 →
  占用人可控制；未被占用 → 已登录用户可控制；其它情况只丢弃输入、画面照旧（协商 `errors=frame` 时
  会收到 `stream.control` 原因帧，Cindy 未启用该协商）。Cindy 不做客户端互斥、也不提供「只读 / 接管」
  按钮；同一画面多个观看者同时输入时以 PSB 的判定为准，多观看者真机行为**尚未验证**。频道归属：
  输入只走工作区级 `adminStreamInput`（会话级串流 / 输入通道已随死面清理删除，见 §8.1 的 IPC 面）。
- **输入能力的宿主边界**：网页 / Electron 拿不到 `Alt+Tab`、`Win`/`Meta`、`Ctrl+Alt+Del`、
  `Ctrl+Shift+Esc` 这类由操作系统优先的组合；全屏下 `Esc` 被浏览器占用（退出全屏）。Keyboard Lock
  只能锁浏览器愿意交出来的键，且可能被版本 / 策略拒绝——不支持时静默降级为事件级捕获，功能
  不受影响，只是仍有少量宿主快捷键可能被本地截走。允许清单（`F5` / `F11` / `F12`；
  Windows / Linux 是 `Ctrl+Shift+I`、`J`、`C`，macOS 是 `Cmd+Alt+I`、`J`、`C`）按设计留给宿主
  自救，是白名单而不是遗漏。
- **宿主光标形状的来源与边界**：形状（XFixes 光标名）由 PSB 客户端上报、经中继转发，Cindy 只负责
  把它映射成 CSS 关键字并在**画面区域**应用：不把形状烘进画面帧、不用远端位图、也不在本机推断
  「这里应该是什么光标」。外观永远由本机指针主题渲染（映射语义与 PSB `@psb/shared` 的
  `stream-cursor.ts` `system` 模式逐条一致，CINDY-RW-09；PSB 的 `host` 位图是可选策略，Cindy 未
  实现）；表外名字 / 缺名字回退箭头 `default`（绝不会变成 `none`）。PSB 客户端不上报时保持宿主
  默认指针，观看与输入都不受影响。契约里的位图字段（边长 64、PNG base64 ≤ 48 KiB、热点在形状内）
  目前仍由主进程**严格校验**——Cindy 只用 `name`，但 PSB 若停发位图字段整条 cursor 帧会被判非法
  丢弃（当前跨仓依赖，变更需双方同步）。光标是**外观**，不代表输入权限或远端是否在接收输入。
- **本轮不提供键鼠输入的高级能力**：不做 Pointer Lock / 相对位移、不做剪贴板双向同步、不做
  多显示器切换、**不提供可调编解码参数**（码率 / 预设等；详情与 HUD 只显示 PSB 下发的编码 /
  解码器名称作诊断）；输入事件单帧远小于 PSB 的 4KiB 上限。滚轮按 CSS 像素发送，
  客户端按「一格 ≈ 100 像素、单次最多 10 格」折算。
- **「远程工作区」页的动作可用性口径（2026-11-26 与 PSB 对齐）**：`capability` 表示「这台客户端
  能不能串流」，`active` 表示「那台机器此刻有没有在采集」（有没有可看的画面；**不是**「中继里
  有没有订阅者」，也不能据此把已有画面切回未启动）。Cindy 用 `capability` 决定是否禁用「启动」，
  用 `active` / `reasonCode` / `desktopSession` / `lastErrorZh` 表达「还没有可看的桌面会话，请到
  PSB 网页远程控制页签启动」（机器判断按码，中文原话只做显示；见 §2.4）。**`status: null` 是
  「此刻读不到」而不是「不支持」**，不能拿它禁用启动。本页的动作按**工作区**工作，不看当前任务
  的 PSB 会话是否终态。
  **本端订阅成功不改写 `active`**：面板先显示「已连接，等待画面…」，首帧到达才显示「串流中」，
  避免零帧时谎称在播。
  页面按**工作区级**工作、不再跟随用户任务的 PSB 会话（任务结束不影响观看），工程口径见
  [PSB 传输契约 §11](../dev-rules/psb-remote-session-transport.md#11-工作区级管理页与观看端绑定2026-11-26)。
- **串流观看端不产生 Agent 会话（2026-11-26 起）**：PSB 0.1.172 的框架规则是「Agent 会话只装
  用户任务」，串流 / 工作区读取走服务接口；Cindy 已改用工作区级订阅，PSB 会话列表与
  `sessionCount` 因此只反映用户任务（产品口径与旧 PSB 的过渡回退见 §2.4 末条）。
- **Cindy 不能保证起「桌面访问」，入口待 PSB 放行（2026-11-26，PSB 0.1.180）**：PSB 拉起访问
  的机器接口是通用网页接口 `POST /api/remote/workspaces/:id/access/start`（幂等 ensure），但
  PSB 的 Cindy Bearer 白名单是**精确形状**（只放行 `/api/cindy/remote/**`），这条路由对 Cindy
  恒 **403**；PSB 台账记的是「Cindy 入口下一轮加」。Cindy 现在只做**非致命**尝试
  （`ensureWorkspaceAccess`：403/404/405/超时/网络失败都不阻断、不报错；结果写进工作区能力位，
  **按能力位编排**：`open` 时前台等待，`unknown` / `failed` / `timeout` 时后台预热、不阻塞「启动」），
  真正的用户
  下一步是**去 PSB 网页的「远程控制」启动访问**，再回来点「启动」。因此：
  - 可以承诺：订阅失败时给出「去网页启动访问」的可行动文案与按钮（§2.4），PSB 中文原话保留诊断；
  - **不要**承诺：Cindy 会自动/保证把工作区访问拉起来（入口存在代码里，但被 403 挡住）。
  这条能力位编排（含 `open` / `unknown` / `failed` / `timeout` 四个分支的前后台取舍）**只有单测级
  证据**，入口被 403 挡住的当下无法真机验证；待 PSB 放行后按 §6 的复验点补一次真机。
  待 PSB 放行后，同一条代码路径即可用（无需改 UI）；跨仓请求见
  [跨仓契约摘要](../collaboration/psb-remote-workspace-contract.md) §1.6 的跟进项（该请求已登记）。
- **不提供协同（Orca）**：远程工作区会话的协同入口在草稿页与会话页都关闭（同一判定点
  `collabEntryPolicy`）。远端没有「拉 Worker」的契约，放行入口会让 main 把 `psb:<id>` 当 SSH
  主机去 preflight（`SSH_HOST_NOT_FOUND`），这是本轮评审拦下的缺陷类型。
- **会话列表来自本机会话行**：判断一条会话是不是远程工作区会话的唯一依据是
  `remoteHostId` 以 `psb:` 开头。网页上由别人创建的会话不会出现在 Cindy 列表里（需要在网页看）；
  同一条会话在 PSB 网页「工作区 › 会话」页签可见，这是用户明确要求的同步。
- **远端模型面按本机目录**：三种 Harness（Claude Code / Codex / Pi）与本地会话同一套，
  远端只吃 AI Gateway 凭据，不复制本机 OAuth；订阅直连与仅本机可桥接的模型来源在远端不出现
  ——与 MCPR 同一条能力边界，不是缺陷。
- **本机路径相关能力不适用**：远端工作区不支持本机 worktree、extra dirs、路径型附件；草稿里的
  工作目录是虚拟引用。图片附件仍按既有缓存交接规则处理。
- **占用是独占而不是排队**：被占用时用户只能等待或换工作区，Cindy 不实现「排队等待自动接手」。
- **透明重建的能力边界（主进程口径，工程细节见工程契约 §6.1）**：
  - **重建只发生在发送那一刻**：Cindy 没有后台定时重建，也不会因为看会话就新建 PSB 会话；用户不发消息
    就一直保持现状（列表与状态照常显示终态）。
  - **远端原生上下文不延续**：新 PSB 会话是全新的远端引擎会话，因此实现上会清掉本地的原生会话 id
    （否则新会话会去 resume 一个不存在的会话而拒绝启动）。Cindy 的消息历史完整；文案按 §2.4 只写
    「可能不会延续」，不承诺恢复上下文。
  - **工作区身份的来源**：旧 PSB 会话行自己带着 `workspaceId`（终态仍可读），因此应用重启后同样能重建，
    本地不需要额外存一份。若 PSB 已经把该会话记录**删掉**、本地又没有工作区线索，Cindy 报「远程会话
    记录已不存在，请新建任务」这类可行动错误，**不会**猜一个工作区建上去。这条是已知缺口：PSB 若将来
    会单独删除终态会话行（而工作区仍在），需要本地增加一列工作区身份并走发版协调。
  - **失败不损坏任务**：工作区被别人占用 / 客户端离线 / 工作区未就绪 / 建立失败时，不重绑、本地任务与
    消息历史不动，界面照实报错（占用还会带占用人名），用户下一次发送会重新尝试。并发发送（含手机、
    排队消息）同一任务只会建一条 PSB 会话。
- **第三个 transport 的身份约束**：`psb:` 与 `mcpr:`、SSH 并列但互不混用；把 `psb:` 当 SSH
  host 会得到错误归因（见工程契约的防回归清单）。

## 7. 验收标准

1. 未登录 / 个人账号时「远程工作区」给出明确原因（需要企业组织），不出现空列表假装没数据。
2. 有可用工作区时，弹窗列出工作区与客户端 / 模板；被他人占用、离线、非 `ready`、不支持 Agent
   的行都出现但禁用且各有原因；不能用「列表里没有」代替原因。
3. 选定工作区即占用（无人占用时先弹占用确认；网页同步可见）；占用被别人抢走时提示占用人并刷新
   列表，**不进入草稿**。
4. 新建工作区期间弹窗保持、按钮禁用、有进度；`provisioning` 期间不能开会话，`ready` 后才可。
5. 草稿页保持原布局（CINDY logo / 输入框 / 示例列表位置不变），位置菜单多一个「远程工作区」渠道；选中后项目胶囊变成工作区下拉（可选现有工作区或新建），**胶囊与下拉行主标题显示工作区实例名 = 目录名**（`directoryName`，如 `saga2_project-3`；缺目录名才回退标题 `title`、机器-短 id），模板名 / 机器名只在行次要信息里；首条消息创建的会话行以
   `psb:<id>` 为远程身份、工作目录是虚拟引用。
6. 会话列表行的图标、状态标签与锁正确反映占用与在线状态（锁 Tip 显示占用人名字，自己占用追加「（你）」）；自己占用的工作区可再开会话。
7. 只有三种外部条件让输入框置灰并给出对应原因：被他人占用、客户端离线、工作区未就绪。PSB 会话
   终态（`stopped` / `failed`）**不锁输入**：下一次发送自动在同一工作区新建 PSB 会话并重绑到同一
   任务，界面不出现「这个任务已经结束」这类死路文案；重绑后出现一行可关闭的中性提示，输入不被阻塞。
8. 会话标题行内、标题后的「…」之后出现文字按钮「远程工作区」（与标题同一行，标题过长时按钮
   不被挤压、标题行高度不变；窗口右上角不再有这个入口）；点它后页签出现在**插件页签那一排标签栏**
   里（与插件窗口同一个内容区容器，不在窗口最右侧另开面板），「+」菜单也能手动加同一页；页签全局
   单例、切任务不消失。两个入口统一走 `openRemoteWorkspaceAdminTab` **单入口**（标题栏按钮直接调，
   「+」菜单经 `useTabCreationMenu` 只额外传显式落点：点哪一排「+」就落在哪一排；组写入 / dock
   展开 / 激活位都由它负责，各入口不再自己算 disabled 条件、也不得事后覆盖页签组）。
   页内页头是**单行 ≤40px** 工作区信息（**实例名（目录名）最显眼** → 模板名 · 机器名 → 占用，
   三块靠左紧凑、固定 16px 间距、不撑开，放不下逐段省略、不换行；目录名就是主标题，**不再单独
   显示目录段**），右侧是靠右的通用操作（占用 /
   解除占用 / 在网页打开，28px、失败给可行动错误）；分类导航左对齐紧凑排列；远程连接里启动 / 停止
