## 1. 什么是 Meka 助理会话

从左侧「Meka 助理」→「Meka 项目」新建的会话，以及**项目目录 / 工作目录等于某个 Meka
项目路径**的会话。它绑定一个 Meka 项目与角色，运行时获得该项目的角色提示词、技能、MCP 与
正式流程能力。

「Meka 助理会话」不是某个固定会话，而是一类会话；侧栏「Meka 助理」段按 Meka 项目分组。
**身份由持久化绑定 `(项目, 角色)` 决定**：只有项目、没有角色（或相反）的会话不算，系统也
不会产生这种半绑定行。

## 2. 隐式规则（2026-11-20 裁决）

- Meka 项目的路径是保留工作区。**用户不需要知道自己是「普通任务」还是「Meka 任务」**：
  只要会话的**项目目录**或**工作目录**（两者都比对；同时命中不同项目时以项目目录为准）
  **精确等于**某个 Meka 项目路径，它就是这个项目的 Meka 助理会话，使用**项目默认角色**。
- 只认**精确相等**：项目目录的子目录、相似前缀都不算；Meka 的旧兜底目录
  （`meka-assistants/<日期>/<id>`）也不参与。
- 该规则在**创建会话时**、以及**未绑定会话被移动 / 切换到该目录时**生效；存量普通会话
  **不追溯**（不会因为目录相同被补成 Meka 会话）。
- 该目录不提供「按普通任务运行」的逃生口；但 Meka 项目配置暂时不可用时，普通任务照常
  能建（按不绑定处理），不会因此失败。
- 从 Meka 助理入口新建时仍可选择角色；其它入口（普通新任务、IM、伙伴、调度等）一律使用
  项目默认角色。
- 正式流程（Jira / GitLab 冻结事项）**不隐式**：仍然只能从桌面显式创建。
- 绑定一旦写入就不可改：已有绑定的会话不能换目录、换项目或换角色；未绑定的旧会话在
  **首次被移入** Meka 项目目录时会补上绑定（存量会话不因路径相同被追溯）。移动 / 迁移 /
  分享若会破坏绑定，系统拒绝或保留绑定，不静默降级。

## 3. 对外是普通会话

对 IM 机器人、伙伴、手机与远程调用方，Meka 助理会话就是普通会话：

- 项目清单里它是普通项目目录（不需要新增「Meka 项目」协议字段）；
- 会话列表 / 选择器不需要认识 Meka。个人 IM 的 `/session` 与 `/ctr` **可以列出并接管**
  Meka 助理会话，接管后由冷启动按持久绑定恢复 Meka 运行时（角色提示词 / 技能 / MCP），
  不会出现「列表里是 Meka、跑起来是普通会话」；
- 官方飞书**没有会话选择器**：官方 hook 的飞书通道不声明 `session-picker-v1`（协议与
  鉴权原因），要正式支持需要跨端协议改动，当前不支持。

外部创建的 Meka 会话与桌面创建的 Meka 会话能力一致；群聊 / 伙伴原有的权限、发言人、
命令面规则不变。

## 4. 边界与验证现状

- 存量 `workspace_kind='meka'` 会话继续按旧数据兼容显示与运行；**不做批量迁移、不回填**。
  新会话不再写这个旧值。
- fork 出的会话只继承完整绑定；`.cshare` 按绑定导出、导入端在本机重新解析项目 / 角色；
  任务迁移遇到 Meka 助理会话显式拒绝。
- **未验证**：上述规则只有代码与新增测试（未跑）依据。以下判据**没有实机证据**：普通入口
  选 Meka 项目目录后落进 Meka 段并使用默认角色；个人 IM 列出并接管后角色提示词 / 技能 /
  MCP 与桌面一致；重启后 IM / 官方 hook 冷启动仍按绑定注入；旧 `kind='meka'` 行行为不变；
  fork / 导出导入 / 协同不丢绑定。官方 hook **新建任务首轮**注入已实现（与冷启动复用同一
  注入入口），但同样**未经实机验证**。
